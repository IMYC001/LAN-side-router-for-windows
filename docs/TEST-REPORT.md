## 0.5.8 直连节点延迟与主题色（2026-10-15）

- 原测试包含经过节点访问 HTTPS 网站的耗时。新增独立直连检测命令，只解析所选节点地址，不执行订阅规则、监听、TUN 或脚本。TCP 类节点测 TCP 建连，Hysteria / Hysteria2 / TUIC 测 ICMP；解析耗时排除，三次有效样本取中间值。阻断 ICMP 不等于节点不能加速，不以零值代替失败。
- TCP 与 DNS 套接字指定源地址和 Windows IP_UNICAST_IF；域名通过绑定网卡的公网 DNS 解析，拒绝本地 / 私网 / CGNAT / fake-IP，网卡与地址必须仍相符。ICMP 指定源 IPv4。测试不修改系统路由、网卡或 Clash；检测超时或取消后子进程退出。
- 新增 Go 检查：TCP / UDP 协议选择、安全节点提取、凭据不进入错误、解析时间排除、中间值、fake-IP 拒绝、取消、ICMP 阻断；Windows 原生 TCP 网卡绑定及 ICMP 回复解析使用回环实际验证。
- 首页加入所选独立节点延迟，每 30 秒刷新，与批量结果同步；节点、订阅或网卡变化时废弃旧检测。Clash 共存模式无法知道其远端节点，显示 `--`，不拿独立订阅或本地代理端口作替代。悬停说明严格使用用户指定文案。

## 0.5.5 转发吞吐优化（2026-10-15）

- 用户最新反馈旧版即使网线直连仍低于 50 Mbps，节点本机测速可跑满。本轮不再暂缓吞吐问题；未启动真实设备网关，未改动 Windows 网络、Clash、驱动或订阅。

- 原固定版本 RACK 在无人工丢包且 FIFO 的路径中误重传：32 MiB 下载三次，无驱动等待时 298.1–315.0 Mbps、979–1013 次重传；模拟每次原生发送等待 2 ms 时 122.5–133.1 Mbps、837–871 次重传。切为传统 SACK/重复 ACK 恢复后同组测试误重传为零。拥塞控制保持 Reno；未采用仅切换 Cubic 的无效实验。
- 批次从 64 帧扩大为 256 帧，严格不超过 256 KiB，保留 1 ms 部分刷新。最终三次 32 MiB 下载：无驱动等待 2028.1 / 2021.4 / 1862.6 Mbps；模拟每次原生发送等待 2 ms 时 616.5 / 613.8 / 590.9 Mbps，均为零重传、零超时。原始输出见 `test-results/throughput-0.5.5.txt`；这是本机模拟对照，不能推断真实设备已经全速。
- Npcap 发送队列改为复用缓冲并一次打包，取消逐帧 DLL 入队。仅加载已安装 DLL、调用 SDK 用户态队列分配/入队进行字节级对照，变长帧编码与 SDK 完全一致；未打开网卡、未调用发送接口。已有 ABI、关闭/取消及收发锁隔离测试继续通过。
- Windows Packet Filter 补齐多帧发送，固定依赖的多帧包装函数会错误扩大 IOCTL 长度，因此按官方 x64 可变结构传递 `16 + 8 * 帧数`，复用中间缓冲。离线检查帧序、数据、指针、大小、复用和非法输入；保留接收 LISTEN 模式。本机未安装此后端，未验证真实驱动收发，不宣称其性能达标。
- 下载丢包、上传丢包、下载乱序、双向丢包加乱序，以及只有一个数据段时的丢包，均完成数据一致性检查；最后一项确认依赖超时重传恢复。故障与批处理测试连续五轮通过。严格字节上限、部分批次刷新、顺序、驱动失败取消、停止/租约失效，以及原生发送途中停止后不再发送排队批次均通过。
